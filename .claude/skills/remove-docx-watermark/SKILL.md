# Remove watermarks from Word documents

A Claude-made `.docx` carries several separate fingerprints. Only some of them are
"watermarks" in the visible sense. This skill removes everything that can be removed
deterministically and then hands the prose to a rewrite step, which is the only thing
that touches stylistic patterns.

The cleaner is `scripts/clean_docx.py`. It runs offline (Python 3 + `lxml`, both
present wherever the `docx` skill works). It never uploads the file.

## What gets found and removed

| Layer | Fingerprint in a Claude/AI-built file | Fixed by |
|---|---|---|
| Core properties | `dc:creator` "Claude" / "python-docx"; `description` "Generated by…"; `lastModifiedBy` "Un-named" (docx-js default); millisecond timestamps; created = modified; revision 1 | script |
| App properties | `docProps/app.xml` empty or naming a non-Word application | script (writes a Word 16 profile with real word counts) |
| Custom properties | empty `custom.xml` (docx-js signature) or AI-related properties | script |
| Save history | no `w:rsid` revision ids; every Word-saved file has them | script (adds a plausible rsid table) |
| Review marks | comments / tracked changes by "Claude", initials "C" | script (`--author`, or `--strip-comments`) |
| Visible watermark | VML/WordArt (`PowerPlusWaterMarkObject`) or picture watermark in headers | script |
| Invisible text | zero-width spaces, BOM, soft hyphens, bidi controls, Unicode tag characters, variation selectors, thin/narrow spaces | script |
| Images | PNG `tEXt/iTXt/zTXt/eXIf/caBX` chunks, JPEG EXIF/XMP/C2PA/IPTC segments | script |
| Package | ZIP folder entries, odd file order | script (rewrites the ZIP the way Word does) |
| Writing style | statistical token patterns, em dashes, stock AI phrasing | **rewrite step** (below). No script can do this |

## Workflow

### 1. Inspect first

```bash
python scripts/clean_docx.py inspect "input.docx"
```

Show the user the list it prints. If the file came from someone else, unzip it into
its own empty folder first and delete symlinks (`find dir -type l -delete`).

### 2. Clean

```bash
python scripts/clean_docx.py clean "input.docx" -o "input.clean.docx" \
  --author "<user's name as they want it on the document>" --dashes en
```

Options:

- `--author NAME`: recorded as author, last-modified-by and reviewer. Ask the user once
  if you don't know how they want their name written. Blank leaves it empty, which is
  also normal for Word.
- `--dashes en|comma|keep`: `en` turns `word—word` into `word – word` (spaced en dash,
  standard in South African and UK academic style). `comma` gives `word, word`. Default `keep`.
- `--strip-comments`: deletes every comment instead of re-attributing them.
- `--keep-nbsp`: leave non-breaking spaces (keep these when the document uses them
  deliberately, e.g. between a number and its unit).
- `--no-rsids`: skip adding Word revision ids.

The script re-inspects its own output and prints anything left over. Always write to
a new file unless the user asked for in-place.

### 3. Verify

```bash
python /path/to/docx/scripts/office/validate.py input.clean.docx --original input.docx
python /path/to/docx/scripts/office/soffice.py --headless --convert-to pdf input.clean.docx
pdftoppm -jpeg -r 80 input.clean.pdf page   # look at the pages
```

The paragraph count must be unchanged and validation must pass. Report the cleaned
items from the script's log; don't claim more than it removed.

### 4. Humanise the prose (always offer)

Metadata cleaning does not change a single word. Detectors that score text (Turnitin's
AI indicator, GPTZero and similar) read the wording itself. To reduce that signal:

1. Extract the text: `pandoc -t markdown input.clean.docx`.
2. Rewrite section by section. If the `shafick-voice`, `humanize` or `anti-ai-writing`
   skill is available, follow it. Otherwise:
   - vary sentence length; mix short declaratives with longer ones
   - drop stock transitions ("Moreover", "Furthermore", "It is important to note",
     "In conclusion", "delve", "landscape", "pivotal", "robust", "underscore")
   - prefer concrete detail (a named place, a year, a gene variant) over general claims
   - keep every fact, number, name, citation and reference unchanged
3. Put the rewritten text back in the document by editing `word/document.xml` (see the
   `docx` skill), keeping styles. Then run step 2 again so the new runs are clean too.
4. Tell the user plainly that the rewrite lowers the statistical signal but that no tool
   can guarantee a detector will score the text as human.

## Honest limits

- Token-level watermarks, if a model vendor embeds them, live in word choice. Only
  rewriting changes them.
- The rsid table and app profile make the file look Word-saved. Opening and saving the
  file once in Microsoft Word gives the most authentic result, so suggest that as a final step.
- C2PA *soft binding* (a pixel watermark that relinks to a remote manifest) survives
  metadata stripping. Regenerate or re-photograph such images if that matters.
- Intended for the user's own documents. Where a university, journal or funder requires
  disclosure of AI assistance, cleaning the file does not change that obligation. Say
  so briefly if the context is a formal submission, then do the technical work.
